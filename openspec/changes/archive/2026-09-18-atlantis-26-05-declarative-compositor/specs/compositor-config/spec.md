## Purpose

The Hyprland session configuration contract: the compositor's
configuration is generated by home-manager as the single source of
truth, built from the upstream example baseline rather than converted
from legacy conf, with content emitted as parser-compatible raw Lua,
per-host display topology from host-level attrs, and no hand-edited
config files participating in the session.

## ADDED Requirements

### Requirement: Home-manager generates the compositor config

The Hyprland session configuration SHALL be generated by home-manager's
`wayland.windowManager.hyprland` module in Lua form, covering binds,
environment, autostart, look-and-feel, input, and window rules. The
repository MUST NOT carry a root `hyprland.conf` that Hyprland could
prefer over the generated file.

#### Scenario: Generated config is authoritative
- **WHEN** the user profile is activated on a host
- **THEN** `~/.config/hypr/hyprland.lua` is a symlink into the Nix store and
  no `~/.config/hypr/hyprland.conf` exists to shadow it

### Requirement: Config content is parser-compatible raw Lua

Config content (sections, binds, env, window rules, autostart) SHALL be
emitted via `extraConfig` as raw Lua mirroring the upstream
`example/hyprland.lua` shapes (`hl.config({...})` tables,
`hl.bind(key, hl.dsp.*(...))` dispatchers, `hl.env("K", "V")` calls,
`hl.monitor({...})` tables). Home-manager typed attrs SHALL carry only
module enablement, `configType`, and package nulling — NOT config
content — because home-manager 26.05's Lua emitter produces shapes the
Hyprland 0.55 parser rejects (evidenced by MR !36: single-string
monitor args, nested env tables, bracket-string window_rule keys,
`col.*` dot syntax, string bind dispatchers, single-quoted strings).

#### Scenario: Typed attrs stay minimal
- **WHEN** `modules/home/hyprland.nix` is inspected
- **THEN** the `wayland.windowManager.hyprland` attrset contains only
  enable/configType/package/systemd settings, and all config content
  lives in `extraConfig`

#### Scenario: Generated Lua parses
- **WHEN** a host boots into the generated config
- **THEN** Hyprland registers the user's binds (not the 3 emergency
  binds) and no error overlay renders

### Requirement: Rewrite from upstream baseline, not conversion

The initial module SHALL be built from the upstream
`example/hyprland.lua` baseline stripped to a minimal session, then
grown by single-addition boot-verified commits. A 1:1 conversion of
the legacy conf chain is explicitly rejected (MR !36 evidence).

#### Scenario: One addition per boot gate
- **WHEN** a config block (section, bind group, env group, rule) is
  added to `extraConfig`
- **THEN** it lands in its own commit, and the host is switched +
  rebooted + bind-count-verified before the next addition

### Requirement: Per-host display topology comes from host attrs

Monitor layout and workspace-to-monitor banks SHALL be declared via
the `banks` list attr and monitor config in each host's `home.nix`,
expanded into `extraConfig` bind lines — not sourced from external
files.

#### Scenario: blackhand triple-head layout
- **WHEN** the blackhand user profile evaluates
- **THEN** the banks list contains DP-3 (portrait, transform 1),
  DP-2 (3840x2160@60, scale 1.5), and DP-1 (portrait, transform 3),
  with workspace banks 1-9 on DP-3, 11-19 on DP-2, and 21-29 on DP-1

#### Scenario: spider single-head layout
- **WHEN** the spider user profile evaluates
- **THEN** a single auto/preferred monitor entry is present and no explicit
  workspace-to-monitor mapping is required

### Requirement: Session support packages come from the home layer

Programs the session autostarts or binds to (waybar, hyprpaper, wofi,
grim, slurp, wl-clipboard) SHALL be installed via `home.packages` in
the Hyprland home-manager module, not `environment.systemPackages` in
a NixOS module.

#### Scenario: WM helper packages resolve in the session
- **WHEN** a Hyprland session starts on either host
- **THEN** waybar, hyprpaper, and wofi are on PATH and the screenshot bind
  executes successfully

### Requirement: Compositor enablement stays on the NixOS layer

The NixOS-layer Hyprland module SHALL keep sole ownership of compositor
installation: `programs.hyprland.enable`, xwayland support, and the
portal `environment.pathsToLink`. The display manager resolves the
wayland-session file from the system layer before any user session
exists, so compositor enablement MUST NOT move to the home layer or
into a base module shared with non-graphical hosts. The module SHALL
NOT carry the session support packages — those live on the home layer.

#### Scenario: One module per layer after the conversion
- **WHEN** any host's module graph is inspected after this change
- **THEN** `modules/nixos/wm/hyprland.nix` contains compositor
  enablement and portal path linking only, and
  `modules/home/hyprland.nix` contains the session config and the
  session support packages

### Requirement: Portal wiring satisfies home-manager 26.05

The compositor NixOS module SHALL link `/share/applications` and
`/share/xdg-desktop-portal` via `environment.pathsToLink` so the
xdg-desktop-portal integration satisfies the home-manager
`useUserPackages` assertion. The linking SHALL travel with the
compositor module rather than being duplicated per host.

#### Scenario: Portal assertion passes at eval time
- **WHEN** any host importing the compositor module evaluates with
  `useUserPackages = true`
- **THEN** evaluation succeeds without the pathsToLink assertion firing
